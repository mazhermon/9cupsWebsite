# MVP: simplify the landing page, move the mixer to its own route

**Date:** 2026-09-29
**Status:** design, awaiting implementation plan
**Goal:** ship a public MVP of 9cups.com

## Problem

`/` currently renders the full four-stem mixer experience. Three things make it
a poor front door:

1. **Slow to first sound.** All four stems (4.4MB total) must download and
   decode through `decodeAudioData` before the play button enables. The
   audience in `PRODUCT.md` arrives on mobile from an Instagram link drop and
   decides in 30 to 90 seconds. Multiple seconds of "Loading the room…" spends
   that budget before anything happens.
2. **No way out to the music.** All five platform links are `#` placeholders,
   so the page cannot convert. The conversion goal in `PRODUCT.md` is currently
   unreachable by design.
3. **The mixer is the whole page.** There is no simpler surface for someone who
   just wants to hear the track and find 9cups on Spotify.

The mixer itself is good work and stays. It stops being the only thing there is.

## Outcome

- `/` is a light landing page: wordmark, one play button wired to the 3D
  terrain, a grouped list of real links, and a CTA into the mixer.
- `/mixer` is today's home page, moved essentially verbatim.
- The site is deployed on Vercel and publicly reachable.

## Decisions taken

| Question | Decision | Reason |
|---|---|---|
| Landing audio source | `9cupsCatchingAFeelingWeb_mix.mp3`, generated by summing the four stems | 660KB vs 4.4MB. Already built (see below). |
| Playback mechanism | `<audio>` element + `createMediaElementSource` | Streams, so playback starts before the full file lands. Time-to-first-sound is the metric that matters for this audience. |
| Landing content | Wordmark, play button, links, mixer CTA, terrain | User chose "wordmark + terrain only" plus the mixer link. The portrait/cover blend stays on `/mixer`. |
| Link targets | Artist profiles, not per-release URLs | More durable; per-release URLs for this track do not all exist. |
| Mixer route | `/mixer` | Reads well as a CTA. |
| Mailing list | `mailto:dj9cups@gmail.com` | Zero backend. An embedded form would need a provider, env vars, validation and spam handling, and would delay the ship. |
| Demo route cleanup | Delete the C-family and font routes; keep `/explore` | Those design decisions are made and recorded in `docs/progress/2026-05-07-state.md`. The ASCII exploration is unfinished. |
| Host | Vercel | Zero-config for Next 16. |

### Already done during design

`public/audio/9cupsCatchingAFeelingWeb_mix.mp3` exists. Built with:

```bash
ffmpeg -y \
  -i public/audio/9cupsCatchingAFeelingWeb_bass.mp3 \
  -i public/audio/9cupsCatchingAFeelingWeb_drums.mp3 \
  -i public/audio/9cupsCatchingAFeelingWeb_main.mp3 \
  -i public/audio/9cupsCatchingAFeelingWeb_vox.mp3 \
  -filter_complex "amix=inputs=4:normalize=0:duration=longest[m]" \
  -map "[m]" -af "volume=-1.5dB" -codec:a libmp3lame -b:a 192k \
  public/audio/9cupsCatchingAFeelingWeb_mix.mp3
```

`normalize=0` prevents `amix` dividing by the input count. The raw sum true-peaks
at +0.7 dBFS, so `-1.5dB` buys clean headroom without limiting artifacts.
Result: 660KB, -10.9 LUFS integrated, -0.6 dBFS true peak.

**Known limitation:** the stems are a **28-second loop**, not the full record.
The landing page therefore loops 28 seconds. Replacing the file with a mastered
full-length mp3 at the same path requires no code change.

### `hooks/useTrackPlayer.ts`

Single-track player. Deliberately not a generalisation of `useAudioEngine` —
the two have different requirements and sharing an abstraction would compromise
both. `useAudioEngine` needs sample-accurate multi-stem sync, which demands
`AudioBufferSourceNode`. `useTrackPlayer` needs fast time-to-sound, which
demands a streaming `<audio>` element.

```ts
interface TrackPlayerReturn {
  ready: boolean          // canplay fired — safe to enable the button
  isPlaying: boolean
  hasStarted: boolean
  error: string | null
  analyser: AnalyserNode | null
  toggle: () => void
}

function useTrackPlayer(url: string): TrackPlayerReturn
```

Behaviour:

- Creates `new Audio(url)` with `loop = true` and `preload = 'auto'`.
  No `crossOrigin` — the file is served same-origin from `/public`, and setting
  it would put the request in CORS mode for no benefit.
- `ready` flips true on the `canplay` event, not on full download.
- The `AudioContext` and the `MediaElementAudioSourceNode` are created **lazily
  inside the first `toggle()` call**, never at mount. Creating a context before
  a user gesture leaves it `suspended` under browser autoplay policy and, on
  Safari, can leave it permanently unusable.
- Graph: `MediaElementSource → AnalyserNode → destination`.
  `fftSize = 2048`, `smoothingTimeConstant = 0.4` — matched to `useAudioEngine`
  so the terrain behaves consistently across both pages.
- `toggle()` pauses/plays the element. It does **not** suspend the context;
  a paused element produces silence and the analyser reads zeros, which is what
  we want for the terrain to settle.
- Cleanup on unmount: pause the element, clear `src`, close the context.
- Errors: the element's `error` event sets `error` and leaves `ready` false.

**Constraint worth recording:** `createMediaElementSource` routes the element's
output through the graph, so the element's own volume is bypassed. There is no
volume control on the landing page, so this does not matter now. If one is added
later it must be a `GainNode`, not `audio.volume`.

### `Terrain` single-source mode

`Terrain` maps four stems onto four displacement layers, each reading a
frequency band via `readBand(stemIndex, lo, hi)`:

| Layer | Band | Currently from |
|---|---|---|
| Rolling hills | bins 1–14 | bass analyser |
| Radial kick pulse | bins 2–8 + `TransientDetector` | drums analyser |
| Wave field | bins 14–95 | main analyser |
| Fine ripples | bins 95–280 | vox analyser |

Add an optional prop:

```ts
/** Drive every displacement layer from one analyser instead of four
 *  per-stem analysers. Bands are unchanged; only the source differs. */
singleAnalyser?: AnalyserNode | null
```

When set, all four `readBand` calls read index 0 of a one-element analyser
array, and the per-stem mute logic plus `uDrumSolo` are bypassed (there are no
stems to mute). The shader, geometry, camera and material are untouched, so the
visual character and the measured 60fps budget carry over.

This composes with the uncommitted `activeKeys` and `dpr` props already in the
working tree; `singleAnalyser` takes precedence over `activeKeys` when both are
passed.

above it. Asymmetric, not a centered stack (`DESIGN.md` anti-patterns).

- `PlayControl` is reused and promoted from its fixed bottom-right position
  into the content flow. Its `play-hint` copy ("Tap shapes to mute") is wrong
  here and gets a prop so the landing page can pass its own or none.

  it to life. This is the "layered reveal" principle: the page rewards the tap.
- The mixer CTA sits below a rule with heavier weight so it reads as a doorway,
  not a sixth pill.
- Mobile (≤720px): single column, terrain height reduced, page may scroll.
  Desktop does not scroll.

### Terrain pointer events

The terrain covers the viewport behind interactive content. `globals.css`
already establishes the pattern (`.hero` is `pointer-events: none`, inner
foreground children take them back). The landing page follows it: the terrain
`<section>` is `pointer-events: none` and the content column re-enables them,
so every link and the play button stay clickable.

## Error handling

| Failure | Behaviour |
|---|---|
| Mix mp3 404s or fails to decode | `error` set; button renders disabled with "Audio unavailable". Links and the mixer CTA still work — the page's primary job survives. |
| `AudioContext` construction throws (older Safari, exhausted contexts) | Caught. The element still plays audibly; `analyser` stays null and the terrain holds its static posture. Audio without visuals beats neither. |
| `play()` promise rejects (autoplay policy) | Caught; `isPlaying` stays false so the button does not lie about state. |
| WebGL unavailable | Terrain is already `dynamic({ ssr: false })`. Wrap in an error boundary so a WebGL failure cannot blank the page; the landing content renders without a background. |

## Accessibility

- Every link is a real `<a>` with `target="_blank" rel="noreferrer noopener"`.
- Play button: `aria-pressed`, plus an `aria-live="polite"` region announcing
  playing/paused so the state is not conveyed by icon alone. (This is the
  `PlayControl` change noted above; `/mixer` inherits the improvement.)
- Terrain is decorative: `aria-hidden="true"` on its container.
- `prefers-reduced-motion`: terrain freezes (already implemented in
  `useReducedMotion`). Audio still plays.
- Visible `:focus-visible` rings, 3px, on all pills and the play button.
- 44px minimum touch targets on pills.
- Skip link retained, targeting the content column.
- Contrast checked at AA against the terrain, which is the page's only
  variable-luminance background. Pills carry their own surface rather than
  sitting as bare text over the wireframe.

## Performance

The terrain now covers the full viewport rather than the right-hand column,
roughly doubling fragment work. Mitigations, in order of preference:

1. `dpr={1}`, `antialias: false` — already the case.
2. The `dpr` prop in the working tree drops to 0.75 if needed.
3. `segments` prop lowers the 180×90 mesh.

Budget: 60fps on a mid-tier device, per principle 5 in `PRODUCT.md`.
**This is verified with a real browser run, not asserted.** If it misses,
mitigation 2 then 3 applies before any visual redesign.

Page weight target: under 1MB for the landing page including the 660KB mix.
